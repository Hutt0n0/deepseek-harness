## 1. 渗透测试侧

### 1.1 "budgeted best-first search" 是错误的框架

**原始断言（00 §2.1）**：渗透测试 = 信念状态上的预算化 best-first 搜索。

**攻击**：best-first search 需要三样东西——可枚举的动作目录、已知的前置/后置条件、
确定（或可采样）的转移函数。渗透测试三者皆无：一个 exploit 是否生效取决于不可观测
的真实状态（补丁级、配置、EDR），转移函数**只有执行才能揭示**，且执行有代价与噪声。
"期望效用最高"这个 frontier 打分在数学上是空的——效用（impact）只在链条终点兑现，
侦察动作的贡献藏在长因果链里。按即时影响打分则永远不派侦察；按"信息增益"打分
则需要一个我们不拥有的世界模型。这不是搜索问题，是**主动推断（optimal experiment
design）**：每个动作是一次区分假设集的实验，假设集 = 关于目标的待验命题（这个服务
存在吗 / 这个版本有 CVE-X 吗 / 这个凭据有效吗），选择标准是每次代价的信息价值，
且受噪声预算约束。另有多智能体干扰：并行 worker 共享观测、共同更新图状态，
pentest 侧的置信度合并同样存在 00 号在审计侧指出的"相关证据稀释"缺陷——
该修正当时只给了审计侧，pentest 侧漏了。

**裁定：修正。** 可执行的替代：

- 图状态以**命题（claim）**为一等公民：节点=实体（主机/服务/凭据/立足点），
  边/命题=关于实体的待验断言，各带 confidence 与证据。调度器读命题集，不读"图"。
- 调度 = 阶段结构（phase 结构显式化：recon→定向→利用→收集，各阶段独立预算）
  + 阶段内打分代理：`prior 成功率 × 条件影响 / (时间成本 + 噪声预算占用 + 风险)`。
  承认这是启发式——没有世界模型就没有原理性 VoI；代价是显式记录每次派发决策，
  供事后调权（见 1.5）。
- pentest 置信度合并同样引入独立/相关区分：不同入口/不同方法收敛同一命题才合并，
  同批 worker 的重复指认只记录不抬分。

### 1.2 OPSEC"三分量代价"在结构上是错的

**原始断言（00 §2.1）**：每动作三分量代价：时间、噪声（触发检测概率）、风险。

**攻击**：把噪声当作每动作的线性独立代价是错的。防御方的检测是**阈值化累积**的：
SIEM 关联规则看的是"5 分钟内同一来源 50 个 404"这类窗口聚合——两个各自安静的
动作在同一时间窗内叠加可以过线。噪声不是加法代价，是**带时间衰减的预算占用**
（类似电池：每动作消耗、随时间回充、上限触发告警），且按目标各自的防御方分账，
不是全局一本账。另外防御方是适应性的，严格说这是博弈不是 MDP；务实立场：
按固定策略防御方建模但取保守阈值，全量记录留做事后分析。

**裁定：修正。** 数据模型后果：OPSEC 台账必须是投影的一部分（对动作事件的确定性
fold：每目标一个衰减累积分），调度器查询它——这是"状态在图里不在上下文里"
原则的又一次落地。每动作的噪声权重是 Config 数据（部署变量），不是常数。

### 1.3 scope 强制：工具层不可判定，出口层是硬前提

**00 §4 缺口 #1** 把执行世界列为"最大缺口"。攻击后裁定：**升级**，且给出论证。

论证：如果 scope 校验发生在工具/argv 层，对 `bash` 是不可判定的——目的地址可以
是运行时计算的（`curl http://$(dig +short x.com)`、DNS 重定向、HTTP 跳转链、
shell 展开）。一个任意程序最终向哪些 socket 发包是**运行时性质**，静态看 argv
推不出来。所以：

- **结论（层位定理）**：scope 强制只能住在**网络出口层**——实验室执行世界提供
  deny-by-default 的出口白名单，任何未被允许的 egress 直接丢弃并告警。
  网络能力不得从模型可调用的裸 bash 泄漏；联网动作走 per-hop 校验的工具
  （fetch 逐跳检查跳转目标）。
- 这同时是提示注入的解毒剂（§3.3）：出口白名单挡住"把数据发到攻击者 URL"。
- **验收测试（可写进任何后续设计档）**：注入测试——让 agent 抓取一个含恶意指令
  的页面（页面指示它 curl 一个范围外主机），断言 egress 阻断 + 告警 + 会话记录。
  这个测试不过，红队模式不许出厂。
- 顺带把合法约束定进去：每目标 qps 上限、时间窗、以及众测场景的边界规则——
  与 scope 同层的确定性策略，不是模型自觉。

### 1.4 frontier 打分器：判断在数据，不在环路

00 号没有回答"谁打分"。攻击一个默认答案：让编排 LLM 自己判断"下一步干什么"——
不可解释、随 prompt 漂移、烧预算的单点故障，且无法跨战役学习（判断力在权重里
不在数据里）。

**裁定：升级为架构原则。** 闭环是"**LLM 提议 → 确定性评分器排序 → 预算门 →
worker 执行 → 图更新**"。LLM 只产出结构化命题与动作候选（参数填充），乘法在
代码里做。防"提议饥饿"（LLM 只提它知道的）：动作目录枚举候选、LLM 填参。
每次派发在台账留一行可解释记录。

### 1.5 经验存储是唯一真正可学习的东西

RL 式地端到端训练编排器不可行（episode = 真实 LLM 战役，成本禁止）。但
`(上下文特征, 动作, 结果, 成本, 噪声)` 元组跨战役累积是可行的，拟合出先验
（此类服务此版本此动作的成功率）回灌 1.4 的评分器。**这是整个 pentest harness
唯一的学习回路**，其余都是脚手架。存储走 storage 接缝；战役数据敏感，本地存储、
共享需 opt-in。

### 1.6 第一期范围边界（防数据模型过度泛化）

内网/AD 式横向是另一类算法（BloodHound 类：权限边上的最短路——顺带承认
"发现图"有强先例，我们的增量在 agent 环路而非图本身）。第一期锁定 web 攻击链；
AD 图谱另立，不许现在的数据模型为它预付复杂度。

## 2. 代码审计侧

### 2.1 Stage 0 的召回天花板与"目录维护跑步机"——但答案不是自建 IR

**原始断言（00 §2.2 Stage 0）**：ripgrep/semgrep 模式扫描枚举候选。

**攻击**：正则枚举 sink 的假阳率不可接受；semgrep/tree-sitter 级语法模式是下限
而非可选。真正的坑是**目录维护跑步机**：每个框架/ORM/模板引擎有自己的 sink 集，
反射与动态分发（`method.invoke`、ORM `.raw()`）永远在目录外。这是 SAST 行业
的已知成本（CodeQL 查询、semgrep 规则的持续维护），不会因为我们用 LLM 就消失。

**裁定：维持 + 补一个自增闭环。** walker 在路径行走中发现的"目录外 sink"回写为
目录候选（走同一 Propose→Ground→Triage 环路，人工确认后入目录）——审计系统
用自己挖洞的机制养自己的目录。这是对"谁维护目录"的唯一诚实回答。

### 2.2 逐对 (source,sink) 行走是错误的计算单元

**00 §2.2 Stage 2 隐含**：按候选对逐个行走。

**攻击**：10 个 source、50 个 sink、共同经过同一个清洗函数——逐对是 500 次行走，
其中去重后 ~60 个不同跳。共享前缀被重复付费，且配对数目本身随组合爆炸。

**裁定：修正。** **后向优先（backward-first）**：从 sink 出发反向行走（调用者、
赋值来源、传参）到 source 或 hop 预算耗尽；sink 语义比 source 更锐利、数目通常
更少（CodeQL 类工具同样 sink 侧主导）。配对验证只在反向前沿与 source 集的交上
做前向确认。配套优化：**hop 记忆化**——step 以 (file, 行区间, symbol, snippet
hash) 内容寻址，行走结果按跳缓存，跨 worker 共享，漂移按 hash 失效。这把
"worker 粒度"老问题一并裁定：按 **sink 簇/模块** 分 worker（行走需要文件上下文
连续性），漏洞类型知识作为 playbook 注入 walker——知识正交于划分，不二选一。

### 2.3 排序先验从哪来：预算是背包不是流水线

Stage 1"top-K"没说 K 按什么分。静态每类型 top-K 忽略类型间 100× 的频率差。
裁定：全局预算 + 按桶（类型×框架×暴露面）的 bandit 再分配，反馈来自 Stage 3
与人工分诊结果。先验特征：模式历史频率、sink 类别基率、代码新近度、公开路由
vs 内部工具、防护密度。冷启动用公开数据 + 自有经验存储，前 N 条分诊后切每库修正。

### 2.4 证据接地的能力边界：锚点 ≠ 语义

**00 §2.2 把 snippet+hash 称为"分水岭"。攻击它**：snippet 只证明"这行代码在记录
时刻存在且长这样"——它固定的是**锚点**，不证明**语义**（"污点真的流过这里"）。
语义断言仍是模型说的。Stage 3 refuter 也攻击不了到底：同族模型共享盲区，跨族
refutation 增加成本且收益必须实测不能假设。

**裁定：修正表述 + 重定位产品指标。** 接地证据分三级说清楚：
1. 锚点级（snippet 可证）——位置诚实；
2. 流级（数据流经此处）——refuter 可提高但不能保证；
3. 可利用级——只有动态证据可证（见 2.7）。
产品指标相应改写为 **precision@人工评审预算** 与**评审员 median 判定时长**，
不是裸 precision。系统的工作是把"每小时人工评审产出的确认真漏洞"最大化。
报告卡片必须带**阴性证据摘要**（"我们在上游 3 跳内找清洗：未找到"）——
这正是让评审员敢点 confirm 的东西，是 UI 与算法的共同设计点。

### 2.5 sanitizer 语义：`broken/restored` 是假阴性制造机（本文最重要的一条）

**00 号（及前史）数据模型**：propagate 步骤带 `taintEffect: kept|broken|restored`；
诊断规则"broken 之后直达 sink 而无 restored = 经典误报形态"。

**攻击**：清洗是**上下文相对**的。HTML 编码对 HTML 文本位是真清洗，对**属性位、
JS 字符串位、URL、SQL、shell 参数**不是。一个 `broken` 位丢失了"防的是什么"：
- 真漏洞被压制：`htmlentities($x)` 标 broken → 该值后来进 HTML 属性位 sink
  （编码不覆盖属性上下文）→ 诊断规则把它归为"疑似误报" → **假阴性**。
- 更糟：诊断规则在**训练模型的行为**——模型学会倾向宣布 broken 来让链路"干净"，
  系统性漏报。错误代价不对称：漏掉一个洞代价是漏洞本身，多报一条代价是几分钟
  评审。**默认必须偏向召回。**

**裁定：修正（数据模型级）。**
- 弃用三值 `taintEffect`。防护以**记录**表达：propagate 步骤可带
  `defense: { mechanism, contexts }`——机制（解析到已知机制目录：DOMPurify 配置、
  `htmlentities` 默认旗标…）+ 它中立的消费上下文集（html-text / html-attr /
  js-string / url / sql / shell-arg / path / header…）。sink 声明自己的消费上下文。
- 链路有效性 = **defense-覆盖-sink-上下文**检查，发生在验证阶段（refuter 按清单
  逐条核），不发生在记录时。fold 保持机械。
- 未知机制按**无防护**处理（召回偏置）。机制断言本身要接地：那个 encode 调用
  得解析到机制目录条目；解析不到就不是防护。
- 老诊断规则反转：broken-直达-sink 不再判"疑似误报"，改为"**声称已防护——
  核对上下文覆盖**"（一个待验证任务，不是 FP 判决）。

### 2.6 存储通道 join：channel 必须升格为节点

**前史模型**：`stored-channel` 是 flow A 的 store 步到 flow B 的 trigger 步的**边**，
channel（介质+定位+键）是边属性。

**攻击**：真实存储型漏洞是 **N 写者 → 1 通道 → M 读者** 的二部join，不是成对
flow 链接。且通道身份是模糊的（"table=comments column=body" vs ORM 模型名——
同一通道两种写法，join 配不上对，孤儿误诊）。自由字符串通道描述 = 又一个
实体解析问题埋在 fold 里。

**裁定：修正。** 通道升格为图节点：worker 记录通道到**每会话通道注册表**
（记录时规范化，冲突当场暴露），写/读边的两端指向通道节点。N:M 组合自然表达，
规范化从 fold 期模糊匹配移到记录期注册。这改写前史的 stored-channel 设计，
进新数据模型。

### 2.7 动态验证桥（PoV）：把最弱环节换成可执行证据

audit 结论永远过不了"你证明了可利用吗"这一问——除非跑起来。对**可运行**的发现：
生成 PoV（请求 payload）→ 实验室执行世界内对插桩实例发起 → 观测效应（标记反射
进输出行 / SQL 报错特征）。成功 → 带**可执行证据** auto-confirm；失败 → 不自动
dismiss（环境不匹配的可能），转人工。这是与纯 SAST+LLM 工具的差异化所在，
也回应 2.4 的第三级证据。代价不免费：需要应用可跑 + 测试数据播种，按独立
工作流预算，不许假装顺路。pentest 侧对应物天然存在：利用成功即 auto-confirm。

### 2.8 taint 是骨干不是全部

authz/逻辑缺陷、竞态、加密误用不是污点可达性问题，图谱不同（状态机/规则审查）。
第一期明确只做污点类 + 目录可表达的确定类；其余记入路线图，**不许**当前数据模型
为它们预付字段。

## 3. 跨切面

### 3.1 置信度校准是产品本体，不是锦上添花

两模式产出都是排序列表由人消费——价值全在校准（0.8 是否意味着 80%）。而 LLM
自报置信度是出了名的不校准。00 号只说了"合并语义要区分独立/相关"，没说置信度
**从哪来**。裁定：显式校准层——特征（路径长、防护存在性、refuter 判决、类别
先验、独立证据数）→ 分诊结果上拟合 isotonic/Platt；冷启动按桶展示经验精度
（"本桶历史 precision 62%"）。校准随分诊数据滚动更新。这是一个正牌 ML 组件，
要有 owner。

### 3.2 评测有效性：对"先度量"本身的度量攻击

00 §5 说"没有 precision/recall 一切调优是盲的"——对，但 DVWA/WebGoat/Juice-Shop
在训练数据里，**基准循环性**：公知漏洞目录与模型知识同源，分数虚高。修正：

1. **commit-pair 挖掘**做主基准：CVE 修复 commit → 引入行/函数级 ground truth，
   分级得分（命中函数 1.0 / 同文件 0.3 / 其他 0）；公开 CVE 数据集（Big-Vul 类）
   同样泄漏，须加**时间切分**（训于旧 CVE、测于新 CVE）与**私有 held-out**
   （自写新漏洞目标）。
2. 补 FP 方向：同目标**已修复版本**上必须零报——测量"把修复当漏洞"的噪音。
3. **成本入榜**：每确认真阳的 $ 与墙钟；报告质量 = 评审员判定时长。质量-成本
   Pareto 是唯一诚实的呈现方式。
4. pentest 侧：靶场 + 里程碑量规（侦察完整度/立足点/提权/数据可达）+
   **OPSEC 分**（触发检测事件数 vs 阈值）——路径质量入分，不只看成败。

### 3.3 harness 自身是第一受害者（提示注入）

红队 agent 全天吞敌意文本：抓的页面、响应头、报错、DB 行，**乃至审计目标的源码
注释**，都可能携带指令。后果：外泄（curl 攻击者 URL 带密据）、scope 说服
（"信我，这主机在范围内"）、审批疲劳社工。缓解天然不完备但必须结构化：
出口白名单（§1.3，挡外泄）、工具结果在上下文中显式标注为不可信数据、高危动词
走审批策略、密据不进 argv（走 env/引用）、台账事后审。并把这个威胁模型写进
harness 文档，配一组注入探针回归集（旧记忆里的 agentsec 想法在此归位：
**harness 必须在自己的靶标面前活下来**）。

### 3.4 无状态 worker：上下文可弃，图可重建

长 worker 会被 compaction 吃掉证据链——模型"忘了为什么这么结论"。规则：worker
的结论只活在图事件里，**任何 worker 从 `query` 各 section 单独重启后行为不发散**
（这是一个可写的 property test：飞行中杀 worker、从图状态重启、断言无分歧）。
在途派发经 jobs 接缝持久化。编排器同理。

### 3.5 语义冲突解决（前史未处理的一类）

前史的"撞名防御"只处理 id 冲突，不处理**语义冲突**：worker A 断言"该参数在
helper X 被转义"、worker B 的链路按原样使用它。裁定：claim 带出处与证据，
图上有冲突态；解决 = 确定性再核派发（第三个 worker 拿双方证据片段回答窄问题）。
语义命题禁止 last-writer-wins。

### 3.6 Stage −1：静态侦察工件（前史缺失）

每个 worker 的首轮都在重读同一批东西。裁定为确定性预计算工件：audit 侧 =
codebase profile（框架识别、路由表、入口点、依赖图、生成/目录排除清单）；
pentest 侧 = target profile（暴露面、技术栈、见过的凭据材料、联络规则）。
两者都做成**投影**（同一机制），一次付费全场复用，同时是 2.3 先验特征的来源。

### 3.7 统一模型问题的裁定：一信封、两图

00 号遗留"统一发现图 vs 每模式一图"。裁定：**信封统一，语义分家**——
节点/flow 的生命周期信封（id、severity、confidence、状态机、证据、provenance、
supersedes 回链）与分诊 UI/报告/生命周期管理共享；**边的语义不统一**
（pentest 边是命题/依赖，audit 边是数据流/通道），因为 1.1 与 2.5/2.6 的语义
根本不同，硬统一会把一边的语义泄漏进另一边（前史 attack-graph 的置信度合并
公式污染 audit 就是实例）。

## 5. 拒绝清单（明确不建，防范围蠕动）

- 不做端到端 RL 编排器（episode 成本禁止）；只做经验存储→先验的离线学习。
- 不自建 AST/IR 服务（v1）；tree-sitter 级模式 + walker 报告目录外 sink 的自增闭环。
- 不让 LLM 在环内打分/乘数（判断在数据不在环路）。
- 不给 audit 无动态证据的 auto-confirm。
- 不做语义统一大图；不做为 authz/竞态预付字段的"通用漏洞本体"。
- 不以模型上下文为任何权威状态的存放处（含编排器与 worker）。
